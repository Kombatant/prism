# Prism

Prism is a standalone Qt 6 desktop application for turning shader-based window animations into installable KWin effects.

It is aimed at KDE Plasma 6 systems where you want to import either:

- a pair of GLSL fragment shaders
- a supported `.kdl` file containing embedded open/close shaders

Prism packages that input as a regular scripted KWin effect under `~/.local/share/kwin/effects/`, reloads KWin, and makes the imported effect available in System Settings.

## What The Application Does

Prism takes shader sources that expose the expected entry points and wraps them in the KWin effect structure needed by Plasma 6. The generated package includes:

- KWin effect metadata
- a JavaScript effect script
- configuration files for the effect
- converted shader files for KWin
- a copy of the original imported source under `contents/raw/`

The application currently supports two animation categories:

- `Window Open/Close Animation`
- `Minimize/Restore Animation`

Each imported effect is installed as its own package, so it shows up alongside other desktop effects instead of being embedded into Prism itself.

## Main UI

Prism currently has three tabs:

- `Import Effect`
  Enter an effect name, choose a category, select shader files or a supported `.kdl` file, and install the generated KWin package.
- `Manage Effects`
  View Prism-installed effects, search them, refresh the list, and remove packages that were previously generated by Prism.
- `About...`
  Shows the app version, author, and project link.

## Import Modes

### GLSL Import

For GLSL-based imports, Prism expects two fragment shaders:

- the first shader must provide `open_color`
- the second shader must provide `close_color`

If you only have one shader file, Prism can reuse the first shader for both directions.

### KDL Import

Prism can also import a supported `.kdl` file when the first selected path ends with `.kdl`, or when the CLI uses `--kdl`.

Current KDL support is intentionally narrow. The file must contain:

- a `window-open` block with a `custom-shader`
- a `window-close` block with a `custom-shader`

If `duration-ms` is present in the `window-open` block, Prism uses that value as the default animation duration for the generated effect.

## Generated Output

Installed effects are written under:

```text
~/.local/share/kwin/effects/<generated-package-id>
```

Package ids follow this pattern:

```text
kwin6_effect_glsl_<category-id>_<sanitized-effect-name>
```

Prism then asks KWin to reload so the newly generated effect becomes visible without a manual restart in the normal case.

## Requirements

- KDE Plasma 6 / KWin 6
- Qt 6 development packages with `Core`, `DBus`, and `Widgets`
- CMake 3.20 or newer
- a working C++20 compiler

This project is Linux/KDE-specific. The generated output targets KWin effects, and the runtime management path depends on local Plasma/KWin configuration and DBus access.

## Build

```bash
cmake -S . -B build
cmake --build build
```

If an existing `build/` directory was copied from another source tree or contains a stale `CMakeCache.txt`, configure a fresh directory instead:

```bash
cmake -S . -B build-prism
cmake --build build-prism
```

## Run

GUI mode:

```bash
./build/prism
```

or, if you used a fresh build directory:

```bash
./build-prism/prism
```

## Command-Line Mode

Prism also supports non-interactive installation:

```bash
./build/prism --install --name "My Effect" --category open-close --first /path/to/open.glsl --second /path/to/close.glsl
```

Supported options:

- `--install`
  Install or replace an effect package without opening the GUI.
- `--name <name>`
  Effect display name.
- `--category <id>`
  Category id. Supported values are `open-close` and `minimize-restore`.
- `--kdl <path>`
  Path to a supported `.kdl` file.
- `--first <path>`
  Path to the first shader file.
- `--second <path>`
  Path to the second shader file.
- `--reuse-first-for-both`
  Reuse the first shader if no second shader is provided.

If `--category` is omitted or unrecognized, Prism falls back to `open-close`.

## How Prism Interprets Shader Inputs

Prism validates input by checking for the expected shader entry points:

- `open_color`
- `close_color`

If either side is missing, installation fails.

Internally, Prism wraps the shader code with KWin-specific uniforms and a generated `main()` entry point so the imported code can run as a KWin fragment shader. It also writes both regular and core shader variants into the generated package.

## Managing Installed Effects

The `Manage Effects` tab lists packages previously generated by Prism by scanning `~/.local/share/kwin/effects/` for Prism-style package ids.

For each package, Prism displays:

- effect name
- category
- source kind (`GLSL import` or `KDL import`)
- package size
- whether KWin currently has the effect enabled

Removing an effect deletes the generated package from disk, removes Prism-managed KWin config entries for that package, and asks KWin to reload.

## Limitations

- KDL import support currently requires `window-open` and `window-close` custom shader blocks.
- Imported shaders must match Prism's expected entry point names.
- Prism can generate and register the KWin package, but final visual correctness still depends on the behavior of the imported shader code inside your Plasma session.
- If KWin reload fails, Prism still keeps the generated package on disk and reports the reload failure separately.
